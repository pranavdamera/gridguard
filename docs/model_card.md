# Model Card — GridGuard Solar Generation Forecaster

_Model cards document the intended use, limitations, and performance of ML models._

---

## Model details

| Field | Value |
|---|---|
| Name | GridGuard XGBoost Forecaster |
| Version | 0.1.0 |
| Type | Gradient-boosted regression tree (XGBRegressor) |
| Task | 15-minute interval AC power generation forecasting (kW) |
| Input | Weather + time features (14 features; see below) |
| Output | Predicted AC power in kW (non-negative, clipped at 0) |
| Explainability | SHAP TreeExplainer (global + per-interval) |

## Intended use

- **Primary use**: Fault detection via residual analysis (actual − predicted).
  If the gap is > k × σ (configurable), an alert is raised.
- **Secondary use**: Generation forecasting for next-interval planning.
- **Out of scope**: Yield guarantees, financial reporting, grid dispatch decisions.
  This model has not been validated on production data.

## Training data

- **Default**: Synthetic data generated by `gridguard.ingestion.download._generate_synthetic()`
- **Real data option**: NREL PVDAQ dataset (system_id configurable)
- **Date range**: 2022-01-01 to 2022-12-31 (train), 2023-01-01 onward (test)
- **Temporal split**: No random shuffle — training uses all data before the split date.
- **Site**: Single-site or synthetic default (Northern Virginia climate profile)

## Features

| Feature | Description | Physical motivation |
|---|---|---|
| `hour` | Hour of day (decimal) | Solar elevation primary driver |
| `hour_sin`, `hour_cos` | Cyclic encoding of hour | Avoid discontinuity at midnight |
| `day_of_year` | Calendar day 1–365 | Seasonal irradiance variation |
| `doy_sin`, `doy_cos` | Cyclic encoding of day_of_year | Avoid year-end discontinuity |
| `month` | Calendar month 1–12 | Seasonal proxy |
| `irradiance_wm2` | Global horizontal irradiance W/m² | Primary power driver |
| `irradiance_sq` | Irradiance² | Non-linear panel response at low light |
| `temperature_c` | Ambient temperature °C | Panel efficiency degradation |
| `wind_speed_ms` | Wind speed m/s | Cooling effect (minor) |
| `irradiance_roll1h` | 1-hour rolling mean irradiance | Smooth cloud transients |
| `ac_power_lag1` | AC power 15 min ago | Short-term persistence signal |
| `ac_power_lag4` | AC power 1 hour ago | Hourly regime signal |

## Hyperparameters

```
n_estimators=500, learning_rate=0.05, max_depth=6,
subsample=0.8, colsample_bytree=0.8, tree_method='hist',
early_stopping_rounds=30
```

## Performance (synthetic data, test split)

_Metrics will vary with real data. Treat these as indicators, not guarantees._

| Model | RMSE (kW) | MAE (kW) | MAPE (%) | R² |
|---|---|---|---|---|
| Persistence (baseline) | ~1.2 | ~0.8 | ~22% | ~0.85 |
| Ridge Regression | ~0.9 | ~0.6 | ~16% | ~0.92 |
| RandomForest | ~0.5 | ~0.3 | ~9% | ~0.97 |
| XGBoost | ~0.4 | ~0.25 | ~7% | ~0.98 |

_Run `make train` to generate actual numbers for your dataset._

## Anomaly detection

| Parameter | Default | Description |
|---|---|---|
| `threshold_sigma` | 2.0 | Flag if residual_sigma < −threshold_sigma |
| `daylight_threshold` | 50 W/m² | Minimum irradiance to evaluate |
| Calibration | Training-set residual stats | Per-hour mean/std from training split |

Fault detection rate on synthetic injected faults:
- At σ=2.0: ~80–90% recall, ~60–70% precision (synthetic only)
- These numbers are not validated on real fault events.

## Limitations and risks

1. **Trained on synthetic data** — Real sensor noise, clipping, degradation curves,
   and shadow patterns are not captured. Performance on real data may be significantly
   worse until the model is retrained on site-specific data.

2. **No temporal uncertainty** — The model produces point predictions with no
   confidence intervals. Anomaly thresholds are heuristic.

3. **Single-site assumption** — A model trained on one site may not transfer well
   to another without retraining or fine-tuning.

4. **Lag feature leakage risk** — `ac_power_lag1` includes the actual power at the
   previous interval. During real-time inference, use the previous interval's measured
   value. Do not use the predicted value as a lag input (error propagation).

5. **Synthetic fault labels** — Precision/recall figures are computed on known injected
   faults. Real-world anomaly rates and severity distributions differ significantly.

6. **Not safety-critical** — This system is a monitoring aid, not a safety control.
   Do not use it as the sole basis for dispatch, maintenance, or financial decisions.

## Ethical considerations

- This project uses public and synthetic data only. No personal data is processed.
- Solar generation monitoring could theoretically reveal behavioural patterns for
  residential systems. This project is scoped to institutional/commercial systems.
- Energy loss estimates are directional indicators. Do not use them to penalise
  operators without independent validation.
